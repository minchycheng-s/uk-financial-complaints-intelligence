# Profiling methodology

Every workbook and sheet is inspected without saving the workbook. Early rows are scored using populated-cell count, FCA terminology observed in the source, uniqueness, text-to-numeric balance and adjacent-row density. Firm-data sheets use identifiers and actual product-group headers such as `Firm name`, `Joint report`, `Reporting period`, `Banking and credit cards`, `Home finance` and `Grand Total`. Notes sheets use a separate product-reference profile anchored by `Product group` and `Product/service name`. The selected row and all alternatives are exported. Profiles record dimensions, merged cells, blanks, duplicates, types, missingness, examples and Excel number formats. Consecutive periods are compared using canonical sheet roles.

Header confidence combines expected anchor matches with the score margin over the second-ranked row. Low-confidence and tied candidates require manual review. Worksheet XML supplies the last value/formula cell, formula counts and merged ranges; this prevents formatting-only cells near Excel's maximum row from inflating the meaningful data range. Exact period-set validation rejects missing, unexpected and duplicate periods. Workbook results are committed to run-level outputs only after that workbook finishes successfully.

Potential totals are limited to exact `Total`, `Grand Total` or `Subtotal` labels in the first populated cell of known metric tables. Potential notes are considered only in Notes sheets and require controlled labels. These indicators are descriptive and never remove source rows.

Structural sheet types determine header anchors and later interpretation: wide complaint metrics, consumer-credit metrics, context rates, firm aliases, joint reporters and product references are treated separately. Column profiles retain the pandas storage dtype but add an explainable semantic type based on header role, Excel format and observed Python value types. Mixed types include parse success and non-numeric examples.

Null objects, empty strings, whitespace-only strings, candidate missing markers, candidate suppression markers, not-applicable markers, Excel errors, zeros and negatives are counted separately without replacement. Excel number-format distributions use only populated data cells below the selected header. Formula metadata distinguishes formula cells from formulas lacking a cached value; the latter may appear null when a workbook is read with `data_only=True`.

Product-group headers are separated from totals and unexpected blank headers. Parenthetical context-rate wording is captured as `measurement_basis`, allowing the stable product group and its reporting basis to be compared independently. Notes taxonomy rows preserve raw group cells, add a clearly derived inherited group for hierarchical review, retain source row numbers and separate footnote markers. Missing Notes sheets are recorded as unavailable reference evidence rather than interpreted as removal of every product.

Notes prose above the taxonomy and footnotes below it are stored as reporting definitions with stable section keys and normalised SHA-256 text hashes. Consecutive periods are compared for additions, removals and wording changes. Schema-change records include original names, positions, storage/semantic types, formats, confidence, evidence and review status. Rename confidence combines text similarity with supporting position and semantic-type agreement, but remains a manual-review suggestion.

Profiling evidence is converted into stable review items. Code may propose an action but cannot approve business meaning. Human decisions are maintained separately in `data/mappings/profiling_review_decisions.csv` and require reviewer identity and date. The extraction gate is approved only when every blocking item is explicitly `approved` or `approved_with_conditions`; pending or rejected items keep extraction unauthorised. Generated Markdown and notebook reports show the same gate and evidence with bounded previews.
